## 피처 배치 (v1)

인덱스 `[0..24]` 는 **25차원 실피처**(사양서 25차원 서브셋과 순서 동일 — 캘린더 8 / 기상 8 / `district_code` 1 /
래그 3 / 이동평균 3 / 변화량 2)이고, `[25..31]` 은 **상수 0 더미 7**(`infra_dummy_0..6`)입니다.

- 따라서 **정보량은 25차원과 동일**합니다 → 성능 차이는 전부 **Optuna 하이퍼파라미터 튜닝 효과**입니다.
- 평가 스크립트는 이 배치를 `MODEL_LAYOUTS["tuned_32d_v1"] = "v1"` 로 알고 있으며,
  **25차원 서브셋 + 0 열 7개**로 행렬을 재현해 평가합니다(2026-10-14 개정).

## 평가

```bash
python benchmarks/evaluate_models.py
# → benchmarks/results/comparison_{timestamp}.json / .md 의 tuned_32d_v1 3행
```

`evaluate_models.py` 는 사양서 §6.1 Temporal Split(test 2025-11-16 ~ 12-31)과
2025 대한민국 실제 공휴일 캘린더(19일)를 적용하며, 25차원 배포본·v2 후보와
**동일한 테스트 행**에서 자기 배치로 평가합니다.

**교차검증 기준** (구 v1 결과 파일 `results/comparison_20261012_233256.{json,md}` 대비):

| 항목 | 구 v1 프레임 | 현행 `전처리_2` 프레임 |
| :--- | ---: | ---: |
| bike R² | 0.9893 | **0.9893** (동일) |
| subway R² | 0.9940 | **0.9940** (동일) |
| subway MAE 개선폭 | −19.2% | **−19.2%** (동일) |

- bike·subway 의 R² 와 subway 개선폭이 소수점까지 일치하므로 **v1 배치 재구성이 정확**합니다.
- 배포본/v1 의 **bus** 수치는 원천 데이터 차이로 이동합니다(v1 R² 0.9908→0.9923). 이는 배치 오류가 아니라
  프레임 차이(구 `시간대별_통합` CSV ↔ `전처리_2` CSV, 버스 타깃 보간 특성)이며 배포본도 같은 방향으로 이동합니다
  (`docs/DATA_PREPROCESSING_HANDOFF.md` P0-1 · `docs/MODEL_PERFORMANCE_REPORT.md` §0.3 참조).
