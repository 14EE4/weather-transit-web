### P0-1. 테스트 구간 `버스_승차` 결측 24.59% — 평가 신뢰도 훼손

**현황 (실측)**

| 분할 | 기간 | n | `버스_승차` 결측 | 비율 |
| :--- | :--- | ---: | ---: | ---: |
| `train` | 2025-01-01 ~ 09-30 | 156,975 | 6,325 | 4.03% |
| `valid` | 2025-10-01 ~ 10-31 | 17,825 | 0 | 0.00% |
| **`test`** | **2025-11-01 ~ 12-31** | **35,075** | **8,625** | **24.59%** ⚠️ |

- `버스_승차` 결측 총 14,950건 = **26일 × 25개구 × 23시간** (완전 일치, 부분 결측 없음)
- 결측 26일: `01/01~01/08`(8일), `06/30~07/02`(3일), **`11/28~12/04`(7일)**, **`12/20~12/23`(4일)**, **`12/26~12/28`(3일)**, **`12/31`(1일)**
- 즉 **26일 중 15일이 테스트 구간**에 집중 → 테스트 성능이 보간값 대비로 측정됨

**영향**
- 버스 모델의 R²/MAPE가 실제보다 낙관적으로 산출되어 **SLA(버스 R² ≥ 0.88, MAPE ≤ 12%) 판정 근거가 약화**됩니다.
- `train` 구간도 4.03%가 보간값이므로, 6/30~7/2 결측이 학습 분포를 왜곡할 수 있습니다.

**요청 (택 1)**
- **(a)** 11~12월 및 6~7월 버스 승차 원천 데이터 **재수집·복구 후 재전처리** ← 권장
- **(b)** 복구 불가 시, **"12월 구간은 버스 평가에서 제외"** 로 합의 (테스트를 `11-01 ~ 11-27`로 축소 → 결측 15일이 **전부** 테스트 구간에서 제외됨) → 사양서 §6.1 수정 필요
- **(c)** 최소한 결측 일자 목록과 **보간 방법을 문서로 확정** (현재 학습 파이프라인은 `선형 보간 → bfill → ffill` 적용 중)

### P1-3. 결측 **대체(Imputation) 책임 소재** 확정

**현황**: CSV는 값을 대체하지 않고 **NaN + 플래그만 기록**한 상태이며, 대체는 학습 파이프라인이 수행합니다. (예: `강수량(mm)` 2,242건이 여전히 NaN)

**문제**: 같은 원천으로 학습·서빙·재학습을 반복할 때, **각 소비자가 서로 다른 규칙으로 대체**하면 결과가 달라집니다.

**요청**: 아래 중 하나로 정책을 확정해 주십시오.

| 안 | 내용 | 장점 |
| :--- | :--- | :--- |
| **(a)** | 원천은 `NaN + 플래그` 유지, 대체는 소비자 책임 ← **현재 동작** | 원본 보존, 소비자별 정책 자유 |
| **(b)** | 원천에 `{컬럼}_보간` 컬럼을 **추가 제공** (원본 값 컬럼은 불변) | 대체 규칙 단일화, 재현성 확보 |

> 어느 쪽이든, **대체 규칙을 문서로 고정**해 주시면 학습 노트북(`benchmarks/CastTransit.ipynb`)에 동일하게 반영하겠습니다.

### P1-5. `강수량(mm)` 결측 2,242건의 원인 구분 요청

- 결측이 **110개 날짜**에 분포하며, 이 중 `AWS_관측행누락 = 1` 은 **271건(12.1%)** 에 불과합니다.
- 나머지 **1,971건**은 **기상 관측 행은 정상인데 강수량만 결측**입니다.
- 현재 학습 파이프라인은 강수량 결측을 **일괄 0.0mm(무강수)로 대체**하고 있는데, 이것이 실제로 "무강수"인지 "미관측"인지에 따라 **학습 라벨이 왜곡**될 수 있습니다.

**요청**: 강수량 결측이 **(i) 실제 무강수(0mm)** 인지 **(ii) 관측 실패** 인지 구분 가능한지, 가능하다면 **결측 사유 코드**를 플래그로 제공해 주십시오.

### P2-2. 컬럼명 표준화

- **결측 플래그**: `{원본컬럼}_결측` 접미사가 원칙이나, 예외 3종(`AWS_관측행누락`, `지하철_자료범위밖`, `풍향0_풍속양수`)이 존재합니다. 규칙 100% 준수 또는 예외 목록 별도 문서화를 권고드립니다.
- **파생 피처 명명 이중화**: 사양서 §3.2는 피처를 **snake_case 영어**(`bike_lag_1h`, `same_day_last_week_sub`)로 규정하나, 실제 학습 CSV 컬럼은 **한글 원천명 기반**(`따릉이_대여_lag_1h`)입니다. → 컬럼 사전에 **영문 표준명 ↔ 실제 컬럼명 매핑표**를 넣어 주시면 온보딩 비용이 크게 줄어듭니다.

### P2-3. 파일 전달 규칙

- 파일명만으로 버전을 구분하기 어렵습니다. **README(또는 컬럼 사전) 동봉**을 권고드립니다. 최소 항목: 생성일시 / 생성 스크립트 경로 / 원천 출처·기준연도 / 컬럼별 의미·단위·결측 규칙 / 이전 버전 대비 변경점.
- 인코딩 UTF-8(BOM 없음), 날짜·타임스탬프 포맷은 **현재 규칙이 정확하며 그대로 유지**해 주시면 됩니다. ✅

## 6. 🔒 모델 입력 계약 — 변경 시 반드시 사전 협의

모델 입력은 **32차원 고정**이며, 순서는 `main.py::build_feature_vector`의 **인덱스 0~31**과 완전히 일치해야 합니다.

| 블록 | 인덱스 | 차원 | 컬럼 |
| :--- | :--- | :--: | :--- |
| 1. 시계열·캘린더 | `0..7` | 8 | `month_sin`, `month_cos`, `hour_sin`, `hour_cos`, `dayofweek`, `is_weekend`, `is_holiday`, `is_rush_hour` |
| 2. 기상 관측·파생 | `8..15` | 8 | `temperature`, `wind_speed`, `humidity`, `precipitation`, `is_raining`, `rain_intensity`, `sensible_temp`, `discomfort_index` |
| 3. 공간(위치) 인코딩 | `16..20` | 5 | `district_code`, `district_subway_stations`, `district_bus_stops`, `district_bike_racks`, `commercial_density` |
| 4. 시계열 래그·이동통계 | `21..31` | 11 | `*_lag_1h`×3, `*_roll_3h`×3, `same_day_last_week_{bike,bus,sub}`, `temp_diff_1h`, `rain_diff_1h` |

> ⚠️ **차원·순서·결측 정책 중 하나라도 변경되면 아래 4곳을 동시에 수정해야 합니다.**
> `models/*.onnx` (재학습) · `main.py` (`build_feature_vector` / `DISTRICT_INFRA` / `prepare_session_input`) · `docs/AI_MODEL_SPEC.md` §3.2 · `benchmarks/CastTransit.ipynb`
>
> 📌 **인덱스 6 `is_holiday` 정의 (2026-10-13 갱신)**: 종전에는 학습에서 상수 0, 서빙에서 `= is_weekend` 로 **서로 달랐고 둘 다 실제 공휴일이 아니었습니다.** 현재는 **2025 대한민국 실제 공휴일 19일 캘린더**를 단일 소스(`main.py::KR_HOLIDAYS` · `is_kr_public_holiday()`, 학습은 동일 집합 `KR_HOLIDAYS_2025`)로 사용합니다. 주말 정보는 인덱스 5 `is_weekend` 가 별도로 담당하므로 **차원 수·순서 변화는 없습니다.** 재학습 산출물과 `models/` 교체 시 이 정의가 반영됩니다.
>
> 📌 참고: 현재 배포된 `models/*.onnx`는 **25차원**이며, 32차원에서 위 P1-1의 7개를 제외한 부분집합입니다. 서버는 `prepare_session_input()`이 입력 차원을 자동 감지해 정렬하므로 25·32차원 모델이 공존할 수 있습니다.

## 7. 🔬 검증 재현 방법

아래 내용을 `audit_preprocessing.py`로 저장한 뒤 `python audit_preprocessing.py`로 실행하시면, 본 문서의 수치를 그대로 재현할 수 있습니다.

```python
# audit_preprocessing.py — 전처리 산출물 무결성/결측 감사
import pandas as pd

df = pd.read_csv("data/2025_서울25개구_교통날씨_전처리_2.csv")
print("shape:", df.shape)

# 1) 완전 그리드 / 중복 / 정렬
print("중복키:", int(df.duplicated(subset=["구", "기준_날짜", "시간"]).sum()))
print("정렬(구별 기준_일시 단조증가):", bool(df.groupby("구")["기준_일시"].is_monotonic_increasing.all()))

# 2) 캘린더 파생 정합
dt = pd.to_datetime(df["기준_날짜"])
print("요일 정합:", bool((df["요일"] == dt.dt.dayofweek).all()))
print("주말여부 정합:", bool((df["주말여부"] == (dt.dt.dayofweek >= 5).astype(int)).all()))

# 3) 결측 플래그 ↔ NaN 1:1
for c in ["따릉이_대여", "버스_승차", "지하철_승차", "기온(°C)", "강수량(mm)", "습도(%)"]:
    print(f"{c}: NaN↔플래그 일치 =", bool((df[c].isna() == (df[c + "_결측"] == 1)).all()))

# 4) 분할 경계 및 수단별 결측(보간 노출도)
print(df.groupby("분할")["기준_날짜"].agg(["min", "max", "count"]))
for split, g in df.groupby("분할"):
    print(f"{split}: n={len(g):,} | 버스 보간 {g['버스_승차'].isna().mean() * 100:.2f}% "
          f"| 지하철 심야 {g['지하철_승차'].isna().mean() * 100:.2f}%")
```

**학습 파이프라인 정합성 검증**: `benchmarks/CastTransit.ipynb` 실행 시 `[Cell 4-B]`에서 **32차원 확정 · 결측 0 · 피처 순서 일치**를 `assert`로 강제하고, `[Cell 7]`에서 생성된 ONNX의 **입력 차원이 32로 고정**되었는지 재확인합니다.
