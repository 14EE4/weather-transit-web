## 1. 요약 (Executive Summary)

기존 학습 자산 2종(**배포본 25차원** / **Optuna 튜닝 후보 32차원**)을 **동일 파이프라인·동일 테스트 구간**에서 비교한 결과:

- **후보(튜닝) 모델이 3개 수단 전 지표에서 우세**합니다. (예: 지하철 MAE −19.2%, 버스 −13.4%, 따릉이 −4.0%)
- 그러나 이 향상은 **입력 차원 증가(25→32)가 아니라 Optuna 하이퍼파라미터 튜닝 효과**입니다.
  - 후보 모델의 32차원 중 추가된 7차원은 **상수 0 더미**로, 정보량이 25차원과 **완전히 동일**합니다.
- 레이턴시는 양쪽 모두 **0.02~0.03ms**로 서비스 SLA(수십 ms) 대비 무시 가능한 수준입니다.
- **결론**: 문서상의 25차원/32차원 표기는 **"모델 입력 텐서(25)"** 와 **"서빙 입력 계약(32)"** 의 **층위 차이**이며, **25차원으로 통일해도 실질 성능 손실이 없습니다.**

## 2. 배경 및 목적

### 2.1 문제 인식
- 사양서(`AI_INFERENCE_MODEL_SPEC.md` §3.2)와 백엔드 문서는 추론 입력을 **32차원**으로 규정하나, `SYSTEM_ARCHITECTURE.md` §6.2 모델 규격 표는 배포 모델을 **25차원**으로 기재하여 문서 간 표기가 상충했습니다.
- `benchmarks/2026-10-12/` 하위에 노트북 export 셀 2회 실행으로 **동일 모델(MD5 일치)이 2벌 중복** 저장되어 있었습니다.

### 2.2 차원 관계 정리
- **25차원 = 32차원 − 7**
  - 제외 7개 = 공간 인프라 4 (`district_subway_stations`, `district_bus_stops`, `district_bike_racks`, `commercial_density`) + `same_day_last_week_bike/bus/sub` 3
- 위 7개 피처는 **현재 학습 원천 CSV에 물리적으로 존재하지 않습니다** (재구성은 가능 — 인프라는 `main.py::DISTRICT_INFRA`, same-day는 `shift(168)`).

### 2.3 목적
1. 기존 자산만으로 **공정 비교**를 수행하고,
2. 성능 향상이 **차원 때문인지 튜닝 때문인지** 분리하며,
3. 25차원 vs 32차원 **문서 모순을 근거 기반으로 정리**합니다.

## 6. 분석

### 6.1 성능 향상의 원인 분해

후보 모델의 32차원 중 **[25–31] 구간은 상수 0 더미**(노트북 `infra_dummy_0..6`)입니다.
즉 후보 모델이 **실제로 활용한 정보량은 baseline과 완전히 동일한 25차원**입니다.

| 요인 | 영향 |
| :--- | :--- |
| 입력 차원 25 → 32 증가 | ❌ **없음** (추가 7차원 전부 상수 0) |
| 하이퍼파라미터 튜닝 (예: `n_estimators=1500`) | ✅ **있음** ← 관측된 향상의 실제 원인 |
| 학습 데이터 / 분할 / 전처리 | 양쪽 동일(변수 통제됨) |

### 6.2 25차원으로 통일해도 손실이 없는 이유

- 32차원의 [25–31]은 **상수**이므로 트리 분기에서 **정보 이득(information gain)이 0**입니다. 차원을 늘려도 모델이 배울 신호가 없습니다.
- 따라서 **"25차원으로 통일"** 은 표현력 손실 없이 다음 이점을 줍니다.
  - 모델 크기 **30.00 MB → 14.13 MB (−53%)**
  - 문서 / 코드 / 학습 파이프라인의 **차원 표기 단일화**
  - 더미 피처 생성·관리 코드 제거 (유지보수성↑)

### 6.3 레이턴시

- 모든 모델이 **0.016 ~ 0.031 ms/row**로, 실시간 추천 API SLA 대비 **수백 배 여유**를 가집니다.
- 차원·크기 증가에 따른 레이턴시 차이는 **실측 불가 수준**입니다.

## 7. 결론 및 권고

1. **문서 모순은 "층위 차이"로 확정**: 32차원 = 서빙 입력 계약, 25차원 = 배포 모델 입력 텐서. **`25 = 32 − 7`**.
2. **차원 표기는 25차원으로 통일**을 권고합니다. (근거: 32차원의 추가 7차원이 상수 0 → 정보 손실 없음)
3. **성능 개선은 튜닝 효과**: 튜닝 하이퍼파라미터를 **25차원 파이프라인에 재적용**하면 동일/유사 향상을 확보할 수 있습니다.
4. 중복 모델 자산(`baseline/`, `hyperparameter/`)은 `2026-10-12/tuned/` 단일 폴더로 **통합 완료**했습니다.
5. **(v2 실측 반영, 2026-10-14)** 실피처 32차원 후보(`benchmarks/2026-10-14/`)는 **지하철에서 전 지표 우세**(MAE −24.9%)했으나 **따릉이는 R²·RMSE 열세, 버스는 MAPE 열세**여서 **전면 교체는 보류**(`models/` 25차원 유지)합니다. 위 2항의 "25차원 통일" 권고는 **v2 실측으로 부분 수정**되며, 최종 확정은 수단별 교체 검토 또는 25차원 재학습 비교 결과로 판단합니다. (§0.2 참조)
6. **(3세대 비교 반영, 2026-10-14)** v1 후보(25차원 정보량 + 튜닝)를 자기 배치로 재평가한 결과 **12개 지표 전부 배포본보다 우세**했습니다(§0.3). 같은 프레임에서 v1 vs v2 를 직접 비교하면 **bike·bus 는 v1, subway 는 v2 우세**입니다. 따라서 ① **25차원 재학습(v2 파라미터)** 실험을 최우선으로, ② 수단별 교체는 **지하철 단독**만 검토 대상으로 권고합니다.

7. **(차원 vs 튜닝 분리 완료, 2026-10-14)** 동일 v2 파라미터 + 25차원 서브셋 재학습(§0.4)으로 교란 3중을 분리한 결과 **개선의 대부분은 튜닝 효과**이고, **차원 증가의 순수 효과는 🚇 지하철에만** 확인됩니다. 25차원 재학습본(`benchmarks/2026-10-14/tuned_25d/`)은 **서빙 정렬이 그대로 맞아** 교체 후보로 등록합니다.
