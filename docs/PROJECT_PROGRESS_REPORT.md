## 1. 개요 (Executive Summary)

본 문서는 **기상 및 대중교통 데이터 기반 실시간/시계열 수요 예측 및 멀티모달 경로 추천 시스템(`weather-transit-web`)**의 분야별 구현 완성도와 실무 배포를 위한 **정형 테스트(QA / UAT / 현장 실측) 진행도**를 종합 진단·정리한 공식 보고서입니다.

개발자/에이전트 중심의 단위 테스트(`pytest`)와 로컬 빌드 검증을 넘어, **인간 테스터가 직접 육안과 실기기(PC/모바일) 환경에서 정형화된 테스트 시나리오를 수행하여 검증해야 하는 잔여 QA 항목**을 명확히 제시합니다.

## 3. 세부 분야별 심층 현황

### 3.1 데이터 전처리 및 증강 (진행도: 엔지니어링 88% / QA 70%)
- **달성 성과**:
  - `data/2025_서울25개구_교통날씨_전처리_2.csv` (209,875행) 및 **2023~2025 3개년 63만 행 신규 통합데이터(`data/통합데이터/`)** 연동 체계 구축.
  - **신규 28열 표준 포맷 개편**: 미사용 5개 열(`지하철_하차`, `지하철_하차_결측`, `풍향(deg)`, `풍향(deg)_결측`, `풍향0_풍속양수`)을 삭제하여 데이터 파이프라인 경량화 및 28열 포맷으로 일원화.
  - **다년도 분할 확장**: 2023+2024년(42.0만 건) Train / 2025년(20.9만 건) 1년 전체 Test 벤치마크 파이프라인 구축.
  - 2025 대한민국 공휴일(19일, `is_holiday`) 및 주말(`is_weekend`) 분리 반영.
  - 20.9만 건 실측 빅데이터 기반 강수량별 비선형 모달 시프트 곡선 교정 (소우 0.5mm 시 따릉이 이용률 -72.8% 급감, 지하철 99.2% 정시성 집중 반영).
  - 2계층 시계열 캐시(`timeseries_cache.py`, Deque + SQLite WAL) 기반 11차원 동적 래그 피처 파이프라인 연동.
- **인간 테스트 및 추가 조치 필요 항목**:
  - **버스 승차 결측 구간(24.59%) 검증**: 11/28~12/04, 12/20~12/23 등 15일간의 보간값 적용 구간에서 모델 예측치가 실제 현실 패턴과 괴리되지 않는지 샘플링 검수.
  - **악천후 인공 시나리오 증강(Synthetic Augmentation)**: 태풍, 기습 폭우(30mm/h 이상), 폭설 등 희귀 극한 기상 상황 데이터의 정성적 보강.

### 3.2 AI 모델 개선 및 서빙 최적화 (진행도: 엔지니어링 90% / QA 65%)
- **달성 성과**:
  - **32차원 실피처 스키마 확정**: 인프라 4종(정류소, 지하철역, 자전거도로 등) + 1주일 전 동시간대 실적(`same_day_last_week_*` 3종)을 통합한 32차원 입력 구조 완성 (`models/feature_schema.json`).
  - **다년도 3개년 기반 Optuna 하이퍼파라미터 최적화 (2026-10-29 최종)**:
    - 🚲 따릉이: $R^2 \approx 0.9894$, $\text{RMSE} \approx 15.88$, $\text{MAPE} \approx 16.08\%$ (전 지표 우세)
    - 🚌 버스: $R^2 \approx 0.9928$, $\text{RMSE} \approx 476.17$, $\text{MAPE} \approx 13.81\%$ (기존 18.09% 대비 -4.28%p 대폭 개선)
    - 🚇 지하철: $R^2 \approx 0.9950$, $\text{RMSE} \approx 674.22$, $\text{MAE} \approx 284.44$
  - **ONNX 경량화 및 실시간 서빙**: 3종 모델을 ONNX 형식으로 서빙하여 25개 자치구 동시 추론 지연시간 2ms 이내 달성 (`GET /health` 검증).
- **인간 테스트 및 추가 조치 필요 항목**:
  - **경계값 및 튀는 값(Outlier) 점검**: 비정상 기상 입력 시 혼잡도가 음수(<0%)가 되거나 100%를 과도하게 초과하지 않는지 육안 확인.
  - **현업 도메인 정성 평가**: 교통 전문가/사용자가 체감하는 시간대별 혼잡도 레벨과 모델 예측 레벨 간 정합성 검토.

### 3.3 지역 및 시간대 선택 기능 (진행도: 엔지니어링 95% / QA 80%)
- **달성 성과**:
  - 서울시 25개 자치구 선택 드롭다운 및 기상청 149×253 격자 좌표 자동 매핑.
  - 사용자 선택 자치구의 브라우저 영구 저장(`localStorage`) 지원.
  - 00시부터 23시까지 24시간 인터랙티브 타임라인 슬라이더 조작 시 매시간 기온(TMP), 강수량(PCP), 하늘상태(SKY), 강수형태(PTY) 예보 데이터 즉각 연동.
  - 출발지/도착지 검색, 자동완성, 스와이프(⇅), 개별 지우기(✕), 일괄 초기화(🔄) 지원.
- **인간 테스트 및 추가 조치 필요 항목**:
  - **25개 자치구 전수 클릭 UI 감사**: 특정 자치구 선택 시 텍스트 잘림, 글리치, 격자 데이터 수신 실패 여부 전수 확인.
  - **모바일 환경 터치 제스처 검증**: 작은 모바일 화면에서 슬라이더 조작 시 페이지 스크롤 간섭 및 터치 타깃 적정성 확인.

### 3.4 교통수단 추천 및 B2B 관제 (진행도: 엔지니어링 95% / QA 70%)
- **달성 성과**:
  - 32차원 ONNX 3종 모델의 실시간 혼잡도 추론과 기상 가중치를 결합한 다목적 효용 추천 알고리즘 탑재.
  - 맑은 날 도보/따릉이 우대, 우천/악천후 시 실내 대중교통(지하철) 우선 추천 뱃지 제공.
  - B2B 모빌리티 대시보드: 자치구별 따릉이 잉여 회수 및 추가 배치 권고 대수, 버스 배차 증차 가이드 산출.
- **인간 테스트 및 추가 조치 필요 항목**:
  - **기상 시나리오별 추천 타당성 검수**: "비가 오는데 따릉이가 추천되는 오류"가 실제로 발생하지 않는지 날씨 모드별 육안 확인.
  - **B2B 권고치 현실성 검증**: 따릉이 잉여 대수 산출 수치가 실제 대여소 거치대 용량 한계를 초과하거나 비현실적이지 않은지 점검.

### 3.5 경로 추천 엔진 및 FactChat LLM (진행도: 엔지니어링 90% / QA 60%)
- **달성 성과**:
  - LangGraph 5단계 StateGraph 노드 기반 멀티모달(도보 + 따릉이 + 버스 + 지하철) 라우팅 엔진 구축.
  - 서울시 공공데이터포털 실시간 버스 도착 정보(`live_bus_arrivals`) 주입.
  - 40+ 주요 환승역 실측 도보 이동시간 및 난이도 데이터(`models/station_transfer_times.json`) 반영.
  - 9호선/1호선 등 수도권 급행열차의 일반역 무정차 통과(Skip) 다이어 및 소요시간 단축 모델링.
  - 구로역·성수역 등 7대 분기역 환승 규칙 및 수도권 시외 운임 특례 적용.
  - FactChat LLM 기반 자연어 AI 경로 추천 요약 브리핑 연동.
- **인간 테스트 및 추가 조치 필요 항목**:
  - **포털 지도(네이버/카카오)와의 실측 대조**: 수도권 핵심 20개 노선에 대해 소요시간, 환승 횟수, 요금 정합성 수동 교차 검증.
  - **LLM 자연어 환각(Hallucination) 감수**: 실제 경로와 다른 엉뚱한 정류소나 노선명을 브리핑에서 언급하는지 사람이 문장 전수 검수.
  - **환승 도보 시간의 현실 체감**: 노원역(4↔7호선 6.2분), 서울역(공항철도 5.5분) 등 실측 환승시간이 실제 보행 피로도와 맞는지 점검.

### 3.6 지도 시각화 인터랙션 (진행도: 엔지니어링 90% / QA 65%)
- **달성 성과**:
  - MapLibre GL JS + OpenStreetMap 타일 기반 인터랙티브 지도, 탑뷰(pitch 0, bearing 0) 고정.
  - 수도권 614개 전철역 토폴로지 및 노선별 고유 색상 렌더링.
  - 수단별 차별화 폴리라인: 도보(점선), 지하철(노선색), 따릉이(녹색 실선).
  - 버스 실노선 폴리라인: 단순 대각선 직선이 아닌 실제 도로 복도(Corridor)를 따라 주행하는 15~35개 도로 좌표열 연동.
  - 추천 경로 선택 시 카메라 자동 이동(`fitBounds` / `flyTo`).
- **인간 테스트 및 추가 조치 필요 항목**:
  - **버스 도로 폴리라인 궤적 전수 점검**: 버스 주행선이 산, 강, 대형 빌딩을 관통하거나 비정상 우회하는 구간이 없는지 육안 점검.
  - **크로스 브라우징 및 WebGL 렌더링 검증**: Chrome, Safari(macOS/iOS), Edge에서 지도 로딩 지연, 마커 겹침 현상, 프레임 드랍 여부 확인.
  - **마커 클릭 엣지 케이스**: 축소(Zoom-out) 상태에서 역 마커 클릭 시 팝업 닫힘 버그나 화면 이탈 현상 테스트.

## 4. 인간 테스터를 위한 정형 테스트(QA/UAT) 체크리스트

### 4.1 환경 준비 및 필수 조건
- [ ] 백엔드 컨테이너 구동: `http://localhost:8000/health` 접속 시 `model_input_dims: 32`, `feature_schema: verified` 확인.
- [ ] 프론트엔드 컨테이너 구동: `http://localhost:3000` 브라우저 접속 (F12 콘솔 에러 0건 확인).
- [ ] `.env` 파일에 기상청 API 키, 서울시 버스 API 키(`BUS_API_KEY`), FactChat LLM 게이트웨이 키 설정 확인.

### 4.2 분야별 정형 테스트 시나리오

#### [테스트 1] 자치구 및 시간 슬라이더 조작
1. 서울 25개 자치구를 순서대로 선택하며, 각 구별 기상청 실황 및 예보 데이터가 정상 갱신되는지 확인한다.
2. 00시부터 23시까지 슬라이더를 1시간 단위로 이동하며, SVG 시계열 차트의 커서와 혼잡도 곡선이 실시간으로 부드럽게 렌더링되는지 확인한다.
3. 브라우저를 새로고침(F5)했을 때, 직전에 선택한 자치구가 유지되는지 확인한다.

#### [테스트 2] 교통수단 추천 및 B2B 관제 화면
1. 기상 조건에 따라 추천 뱃지(예: 쾌청 시 따릉이 우선, 우천 시 지하철/버스 우선)가 상식적으로 표출되는지 확인한다.
2. B2B 모빌리티 대시보드로 이동하여, 25개 자치구별 따릉이 회수/추가배치 대수가 현실적인 수치 범위(10~150대) 내에 있는지 확인한다.

#### [테스트 3] 수도권 대표 10대 경로 실측 대조 테스트 (vs 카카오/네이버맵)
아래 10개 대표 경로를 검색창에 입력하고, 카카오맵 대중교통 경로와 대조하여 검증합니다.

#### [테스트 4] 지도 시각화 및 인터랙션
1. 경로 카드를 클릭했을 때 해당 경로 전체가 화면 안에 들어오도록 카메라가 부드럽게 줌/이동(`flyTo`)하는지 확인한다.
2. 버스 구간의 보라색/주황색 도로 폴리라인이 한강이나 산을 가로지르지 않고 실제 도로 축을 따르는지 확인한다.
3. 지도를 최대로 축소(Zoom-out)한 뒤 임의의 지하철역을 클릭했을 때 팝업이 바로 닫히지 않고 정상 유지되는지 확인한다.
4. 모바일 화면(폭 375px~430px)에서 하단 시트 및 지도가 레이아웃 깨짐 없이 동작하는지 확인한다.
